# Security Audit — Nova Stream, May 2026

**Scope:** All code on `claude/nextgen-iptv-platform-rEZiD` as of HEAD.
**Reviewer:** Senior application-security engineer.
**Methodology:** White-box review (source + infrastructure), threat-modelled per
service, mapped to OWASP Top 10 (2021) and OWASP API Top 10 (2023).

This audit catalogues every issue we found, ranks it by severity, gives an
exploit narrative, and links to the commit that fixes it. Items marked
**FIXED** were addressed in the same commit as this document; items marked
**TRACKED** have a follow-up issue.

Severity scale: **Critical** (active exploit available, prod-blocker) ·
**High** (exploitable under common conditions) · **Medium** (defence in depth) ·
**Low** (hygiene).

---

## 1. SSRF in playback proxy via attacker-controlled segment URL — Critical [FIXED]

**File:** `services/playback/internal/playback/proxy.go`

**Issue.** The proxy validates that the caller holds a valid playback ticket,
then fetches whatever URL is in `?u=` (segment) or `?v=` (variant):

```go
func (p *ProxyHandler) serveSegment(...) {
    upstream := r.URL.Query().Get("u")   // attacker-controlled
    req, _ := http.NewRequestWithContext(ctx, http.MethodGet, upstream, nil)
    resp, err := p.client.Do(req)
    ...
}
```

**Exploit narrative.** Any authenticated user mints a playback ticket
(`/play/{id}/master.m3u8?token=...`). They then call directly:

```
GET /play/{id}/seg/x?token={valid}&u=http://169.254.169.254/latest/meta-data/iam/security-credentials/
```

The proxy fetches the AWS instance metadata service and proxies the response —
**leaking IAM credentials**. The same attack reaches internal admin endpoints
(`http://localhost:9001/`, `http://grafana:3000/`), Postgres via `http://`
front-ends, and any other RFC1918 / link-local address reachable from the pod.

**Fix.** Lock the proxy to the origin tied to the ticket and a domain
allowlist. URLs are no longer accepted as query parameters; instead we
remember the parsed origin URL on the ticket, and segment paths are
referenced by an opaque content-hash that the proxy resolves server-side.
A `dialNonInternal` transport-level guard refuses dials to RFC1918,
link-local, loopback and cloud metadata IPs even when DNS resolution is
attacker-controlled (DNS rebinding defence).

## 2. SSRF in playlist / EPG / recording fetchers — Critical [FIXED]

**Files:** `services/playlist-ingestion/internal/ingest/fetcher.go`,
`services/epg/internal/epg/ingest.go`,
`services/recording/internal/recorder/recorder.go`.

**Issue.** All three services fetch URLs that originate from user-supplied
input (M3U/XMLTV source URL, HLS manifest containing arbitrary segment
URIs). Today they use a vanilla `http.Client` which honours DNS results and
follows redirects to any address.

**Exploit narrative.** A tenant creates a playlist source pointing at
`http://169.254.169.254/latest/meta-data/`. Ingestion fetches it. The
parser treats the response as M3U (mostly fails, but the connection
happened and the metadata was read). For sources that follow redirects an
attacker can publish a public URL that 302s to `http://internal-admin:8080/`
and exfiltrate the body via the error message we log.

**Fix.** All three services now share a single `safehttp.Client` from
`libs/go/pkg/safehttp` that:

* refuses to dial RFC1918, link-local, loopback and cloud metadata IPs at
  the transport level (`net.Dialer.Control` rejects after resolution),
* re-validates the destination after each redirect,
* caps redirects at 5,
* caps response size (16 MB for playlists, 256 MB for EPG, 64 MB per HLS
  segment) so a hostile origin can't OOM us.

## 3. Argon2id used for refresh-token lookup — High [FIXED]

**File:** `services/auth/internal/auth/service.go`, function `hashOpaque`.

**Issue.** Refresh tokens are 32 bytes of cryptographic randomness, but
they were hashed with Argon2id for lookup. Argon2id is a **password** hash
(slow on purpose: 2 iterations × 64 MB × 4 parallelism). Every refresh
call burns ~100 ms of CPU just to look the row up, and the salt was
hardcoded — defeating Argon2's purpose entirely.

**Exploit narrative.** Denial of service: a misbehaving client refreshing
once per second pegs an entire CPU core per active session. At
10,000 active users you saturate the auth service.

**Fix.** Refresh tokens now hash with HMAC-SHA-256 keyed on the per-
deployment pepper. Argon2id remains for **passwords** (where slowness is
the point). The DB column is still `BYTEA(32)` and the lookup is unique-
indexed.

## 4. No brute-force protection on login — High [FIXED]

**File:** `services/auth/internal/auth/service.go`.

**Issue.** Login accepts unlimited attempts per email / per IP. Combined
with the standard "invalid credentials" response (no timing differentiation
yet) an attacker can spray credential-stuffing lists.

**Fix.** Two-tier rate limit:

* **Per-account:** Redis-backed sliding-window — 5 failed attempts in
  15 minutes locks the account for 15 minutes; the *user* sees the same
  "invalid credentials" message regardless, so this doesn't double as an
  account-enumeration oracle.
* **Per-IP:** existing gateway rate limiter (60 req/min) covers volumetric
  attacks; we additionally annotate `/auth/login` as a sensitive route
  with a 10 req/min cap.

Successful login resets the counter. After three lockouts in 24 hours we
notify the account holder by email (a future commit; tracked).

## 5. Race condition in refresh-token rotation — High [FIXED]

**File:** `services/auth/internal/auth/service.go`, function `Refresh`.

**Issue.** The refresh code does SELECT → UPDATE in two statements. Two
concurrent refresh attempts with the same token (browser + service worker,
say) can both pass the `used=false` check before either UPDATE runs.
Result: two valid token pairs are issued, and the chain-revocation
defence is bypassed.

**Fix.** Atomic compare-and-set in a single statement:

```sql
UPDATE refresh_tokens SET used = true
 WHERE token_hash = $1 AND used = false AND revoked = false
 RETURNING user_id, chain
```

If zero rows returned, we hit either replay or reuse — revoke the chain
and reject. The check, the swap, and the chain decision happen inside
one Postgres row lock.

## 6. JWT does not validate `iss` / `aud` — Medium [FIXED]

**Files:** `services/gateway/internal/gateway/auth.go`,
`services/auth/internal/auth/service.go`.

**Issue.** The gateway verifies the signature and expiry but accepts any
issuer and any audience. If an attacker obtains our public key and a JWT
signed by an unrelated service in the same trust domain, the gateway
accepts it.

**Fix.** Auth signs with `iss=nova-stream-auth` and `aud=nova-stream-api`.
Gateway parses with `jwt.WithIssuer(...)` and `jwt.WithAudience(...)`
options so unknown issuers / audiences fail signature validation outright.

## 7. CORS unconfigured on the gateway — Medium [FIXED]

**File:** `services/gateway/internal/gateway/wire.go`.

**Issue.** The webOS app and the Next.js web app live on different
origins than the gateway. Without explicit CORS headers, browsers block
the XHR; today we work around this only because the webOS launcher
redirects to the same origin as the gateway in production. As soon as
the gateway lives on `api.novastream.tv` and the app on
`app.novastream.tv` the entire web/TV layer breaks.

**Fix.** Explicit CORS middleware: allowlist of `https://app.novastream.tv`,
`https://staging.app.novastream.tv` and `http://localhost:3000`, methods
`GET POST OPTIONS`, exposes `Authorization`, max-age 600s. No wildcard,
no credentials with wildcard.

## 8. No security headers on the gateway HTTP response — Medium [FIXED]

**File:** `services/gateway/internal/gateway/wire.go`.

**Issue.** Next.js sets HSTS / nosniff / X-Frame on its own responses,
but the gateway proxies / GraphQL handler does not. A reflected-content
issue at the gateway would render in-browser without protection.

**Fix.** A `securityHeaders` middleware sets:

```
Strict-Transport-Security: max-age=63072000; includeSubDomains; preload
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
Referrer-Policy: strict-origin-when-cross-origin
Content-Security-Policy: default-src 'none'; frame-ancestors 'none'
Permissions-Policy: interest-cohort=()
```

CSP is `'none'` because the gateway only returns JSON; no inline scripts.

## 9. Email enumeration on registration — Medium [FIXED]

**File:** `services/auth/internal/auth/service.go`.

**Issue.** Calling `register(email)` for an email that already exists
returns a Postgres unique-violation error, distinguishable from the
"created" response. Attackers enumerate which emails are subscribers.

**Fix.** Register always returns the same generic "check your email"
response. If the email exists we instead send a *password-reset hint*
email and skip the user-creation step; the attacker's response is
identical to the "fresh registration" path.

## 10. Passwords aren't checked against breach corpora — Medium [TRACKED]

Recommend: integrate the HaveIBeenPwned k-anonymity API at registration
and password change. Reject the most-common 100,000 passwords outright.
**Status:** schema and config hooks in place; HIBP client deferred.

## 11. No 2FA / MFA — Medium [TRACKED]

Account credentials alone unlock playback and billing. We need TOTP
(RFC 6238) at minimum, with WebAuthn as the recommended path. Tracked as
a separate workstream because it changes login UX significantly.

## 12. Postgres connection strings allow non-TLS in production — Medium [FIXED]

**Files:** k8s manifests, all `DATABASE_URL` references.

**Issue.** `sslmode=disable` was hardcoded in docker-compose for dev
convenience and copied into example configs. In production this would
allow MITM of credentials.

**Fix.** All k8s `DATABASE_URL` secret examples now use
`sslmode=verify-full`. A startup check refuses to boot if
`DATABASE_URL` contains `sslmode=disable` while `NS_ENV=production`.

## 13. Recording worker accepts arbitrary segment hosts — High [FIXED]

**File:** `services/recording/internal/recorder/recorder.go`.

**Issue.** An HLS manifest from a tenant-controlled source can include
absolute URIs pointing at internal services. The recorder fetches them
and writes them to object storage — turning DVR into a covert exfiltration
channel.

**Fix.** Recorder reuses the same `safehttp` client as the playlist
fetcher; in addition we constrain segment URLs to either the manifest's
own scheme+host **or** a per-source allowlist of approved CDNs.

## 14. Playback ticket signing key is symmetric and lives in env — Low [TRACKED]

Today `TICKET_SIGNING_KEY` is one symmetric secret per cluster. Rotating
it invalidates every in-flight ticket. Track migration to a key-id-tagged
HMAC with two active keys (current + previous) so rolling rotation
becomes possible.

## 15. Catch-up manifest exposes viewer ID in segment query — Low [TRACKED]

`dvr.ManifestBuilder.signSegmentURL` embeds the viewer's user ID into the
signature input; the segment URL therefore embeds it as `vt=...` (it's
also used in cache-key calculations). Replace with a session-scoped
opaque token issued at manifest-build time so the user ID never leaves
the server.

## 16. Audit logging absent — Medium [FIXED]

Login, failed login, refresh, password change, MFA challenge, subscription
change, device add / revoke now write rows to `auth_audit_log` with
`event`, `user_id`, `ip`, `user_agent`, `at`. Retention 90 days.

## 17. Activation, password-reset, and unsubscribe tokens — High [FIXED]

New email-driven flows ship with single-use, time-limited tokens stored
hashed (HMAC-SHA-256 with the auth pepper); plaintext tokens are emitted
once to the user, never logged, never persisted in plaintext.

## 18. Stripe webhook signature verification — Medium [FIXED]

The subscription service exposes `/webhooks/stripe`. Without signature
verification an attacker would POST forged events ("subscription
activated, free pass!"). We use Stripe's official Go SDK
`webhook.ConstructEvent` with the per-environment signing secret.

## Out-of-scope but recommended

* **Threat-model exercise** before GA — STRIDE-per-service, two days with
  a fresh pair of eyes.
* **External pentest** before public launch.
* **Bug bounty programme** (HackerOne / Intigriti) for ongoing coverage.
* **Annual third-party audit** of crypto choices.
* **SLSA L3 supply chain** — sign container images with cosign + attest
  builds via SLSA provenance.
